# MASTER COMMAND — WEB LIVE MULTI-SUBJECT ARCHITECTURE
## PHASE 1 — FREEZE BASELINE + AUDIT + DESIGN

Tôi cung cấp **phiên bản WEB LIVE hiện tại đang hoạt động ổn định** làm nguồn duy nhất để phân tích.

Mục tiêu dài hạn:

> Kế thừa WEB LIVE hiện tại và phát triển thành hệ thống LIVE chuyên biệt cho:
>
> 1. TIN HỌC THCS  
> 2. ĐẠI SỐ THCS  
> 3. HÌNH HỌC THCS

Kiến trúc mục tiêu:

```text
WEB_LIVE_BASELINE_FROZEN
        │
        ▼
   WEB_LIVE_CORE
        │
        ├── INFORMATICS_PROFILE
        │
        ├── ALGEBRA_PROFILE
        │
        └── GEOMETRY_PROFILE
```

NGUYÊN TẮC QUAN TRỌNG:

**KHÔNG tạo 3 WEB LIVE độc lập.**

Phải ưu tiên kiến trúc:

```text
ONE CORE
+
SUBJECT PROFILES / MODULES
```

để các chức năng chung chỉ tồn tại và được bảo trì tại một nơi.

# 2. FREEZE BASELINE

Xác định chính xác source WEB LIVE được cung cấp.

Tạo:

```text
WEB_LIVE_BASELINE_FROZEN
```

Ghi nhận tối thiểu:

```text
BASELINE_NAME =
BASELINE_VERSION =
BASELINE_SHA256 =
BASELINE_STATUS = FROZEN
SOURCE_MUTATED = NO
```

Nếu source là ZIP:

1. tính SHA256 ZIP gốc;
2. giải nén sang vùng làm việc;
3. không thay đổi ZIP gốc;
4. ghi nhận cấu trúc source;
5. tính fingerprint/hash phù hợp cho source đã giải nén.

Mọi phân tích tiếp theo phải truy ngược được về baseline này.

---

# 4. PHÂN LOẠI COMPONENT

Phân loại các thành phần hiện tại thành:

```text
A. CORE_SHARED
B. SUBJECT_SPECIFIC
C. LEGACY
D. UNKNOWN
```

## A — CORE_SHARED

Các chức năng có thể dùng chung cho cả ba môn, ví dụ:

- lesson loading;
- navigation;
- teacher control;
- TV rendering;
- focus;
- answer/hint;
- fullscreen;
- keyboard control;
- media;
- animation;
- state management;
- packaging;
- common UI.

Chỉ kết luận sau khi audit source.

## B — SUBJECT_SPECIFIC

Chức năng có logic gắn với:

```text
informatics
algebra
geometry
```

Phải chỉ rõ dependency.

## C — LEGACY

Code còn tồn tại nhưng không còn tham gia runtime chính.

Không xóa.

## D — UNKNOWN

Không đủ bằng chứng để phân loại.

Không suy đoán.

# 12. SUBJECT DETECTION

Thiết kế cách xác định môn.

Ưu tiên explicit metadata:

```text
subject_engine
```

Không ưu tiên đoán môn từ nội dung.

Ví dụ:

```text
subject_engine = geometry
```

WEB LIVE tự kích hoạt:

```text
CORE
+
GEOMETRY_PROFILE
```

Nếu lesson cũ không có metadata:

Thiết kế fallback an toàn, ví dụ:

```text
subject_engine = legacy/default
```

Không được làm lesson cũ crash chỉ vì thiếu subject_engine.

---

# 13. PROFILE ISOLATION

Kiểm tra kiến trúc đề xuất phải bảo đảm:

```text
GEOMETRY_PROFILE
```

không làm thay đổi runtime của:

```text
ALGEBRA_PROFILE
INFORMATICS_PROFILE
LEGACY
```

Tương tự cho các profile khác.

Mục tiêu:

```text
SUBJECT FEATURE
→ SUBJECT PROFILE ONLY

COMMON FEATURE
→ CORE
```
